## What the graders noticed

**`codex:default`**
- picture: The 'try' step (change n == 0 to n == 2) makes the base case stop at countdown(2), so the tree gets only 2 nodes. The lesson never says what to expect, and with countdown(3) that change is confusing. Also, countdown(1) and countdown(0) would never be reached in that case, which could mislead the learner about how the base case works.
- picture: The code builds a binary-tree dict with 'left'/'right' keys but only ever uses 'left', so the picture is a chain. This adds unneeded structure (right is always None) and the 'box inside a box' metaphor does not match a tree drawn with boxes beneath each other. The lesson also never explains what the 'value' string or the tree picture represent, beyond calling each box one call.
- picture: The lesson text says the box 'returns to the waiting call' and 'attaches the returned picture', but the code does nothing on the return path except return the node. The attaching happens when the result is assigned on line 5, before the return. The explanation of how return values flow back is muddled, and the lesson defers 'How do recursive calls return answers?' to a next question. The learner also never sees the calls actually happen in order, since the picture only shows the finished structure.
- picture: Line 4's line-by-line explanation says 'with its attached boxes', but the base case box has no children attached yet.

**`claude:sonnet`**
- picture: The nesting-doll analogy is linear (one doll inside one doll), but the code branches into two calls per level. The lesson never connects the analogy to the branching tree, so the picture and the analogy don't line up.
- picture: The [try] suggestion 'Change n < 2 to n < 3' makes fib(4) return 5, which is no longer Fibonacci, and the lesson doesn't say what to expect. A learner could take it as a bug or a mistake. The suggestions are bare and have no prompts about what to notice.
- picture: fib is a heavier first example than a single-branch function like factorial or countdown. The tree repeats fib(2), fib(1) and fib(0) without comment, and the margin note says 'forever' where the quiz says RecursionError. The quiz tests only the base case, not the shrinking step or the bottom-up flow.
- picture: The Russian nesting dolls analogy describes linear recursion, which contradicts the branching tree recursion used in Fibonacci.

**`claude:opus`**
- picture: The nesting-doll analogy is linear (one doll inside one doll), but fib branches into two calls. The lesson never says where the analogy stops fitting, which may confuse a learner when the tree appears.
- picture: The code returns a (value, node) tuple and builds dicts for the picture. That bookkeeping sits inside the very function meant to show the bare idea, so a beginner has to read past it. A simpler first example such as factorial or countdown would be gentler, with fib as the follow-up.
- picture: The quiz only checks that the base case is needed. It does not test tracing the calls or the order in which answers return, which the lesson stresses. The 'try' prompts are bare commands that don't say what to expect.
- picture: Russian nesting dolls illustrate linear recursion, but Fibonacci is branching tree recursion (dolls do not split into two).

**`antigravity:flash`**
- picture: The [try] suggestion 'change n <= 1 to n == 0' makes fib(1) call fib(0) and fib(-1), so it recurses forever and crashes. The lesson doesn't warn about this or tie it to the quiz, so it can confuse a learner who only knows a little.
- picture: The lesson never says that fib is the Fibonacci sequence or what fib(n) is supposed to compute. The nodes show fib(1) = 1 and fib(0) = 0, but the parent nodes show no values, so the learner can't see how the calls combine into an answer. This also makes the example harder to follow than a simple countdown or factorial.
- picture: The explanation is thin and a bit loose. It says the function 'runs forever' when Python actually raises a RecursionError, and the single tree picture is never walked through node by node. The mirrors and dolls analogies are only loosely linked to the tree, and the quiz tests recall of the base-case idea more than understanding of how the tree forms.
- picture: The function builds a visualization tree rather than adding left + right, which may blur the distinction between computing Fibonacci and constructing a tree data structure.

**`antigravity:flash-high`**
- picture: Quiz is wrong/misleading: removing the base case makes fib(n-1)/fib(n-2) go to negative numbers forever, so it does raise RecursionError, but the 'why' says 'smaller and smaller numbers' loosely and the text says 'fib(3) cannot compute instantly' without ever explaining return order; also the text says fib(3) spawns 'fib(2) and fib(1)' but never mentions fib(0) or why fib(1) appears twice/fib(0) appears, so the 5-node picture is not explained.
- picture: Fibonacci is a heavy example for a first look at recursion: the tree mixes two branches and a duplicated fib(1) leaf, and the text never ties the picture's leaf labels (fib(1) = 1, fib(0) = 0) back to the narrative. Simpler countdown/factorial would introduce the idea more gently; the mirrors and dolls analogies are also stacked before the real term is shown in code.
- picture: Line-note/text inconsistencies: base-case text says 'n <= 1' returns a leaf but never explains why n=0 and n=1 return themselves; the 'try' item 'Change n <= 1 to n <= 2' and the swap suggestion have no explanation of what to expect, and the code shows the tree, not the final numeric result of fib(3), so learners never see 'those leaf answers travel back up' assembled into a value.
- picture: The text says leaf answers travel back up to assemble the final result, but the code only builds a tree structure and never computes the Fibonacci sums for parent nodes.

**`copilot:auto`**
- picture: The tree nodes show running totals ("3 + 3", "4 + 6"), but the text says the total is 4+3+2+1+0. Nothing explains why the picture reads differently, and the lesson never says which way to read it (top is sum_to(4), bottom is sum_to(0)).
- picture: The code returns a (total, picture) tuple and builds dicts alongside the arithmetic. A beginner has to untangle that before seeing plain recursion, so the picture code hides the idea. Lines 8-9 have no plain-English note either.
- picture: The terms "base case" and "call stack" are never introduced; only "stopping point" appears in a margin note. The quiz is just arithmetic (4+3+2+1+0) and doesn't check understanding of the stopping condition or the order of calls, and the [try] items give no hint of what to expect (e.g. n == 1 prints 9).
- picture: Embedding visual tree-building dictionary syntax into the recursive function clutters the core recursion concept for a beginner.

**`antigravity:claude`**
- picture: The call tree is hardcoded as a literal dict rather than built from the recursion, so it isn't a real picture of the code's behavior. It also has 0!=1 at the bottom with 5! missing: the tree shows only 5 nodes (0! to 4!) and omits the root factorial(5), contradicting the table's 6 rows. The 'root': True flag is on 4!, which is misleading.
- picture: The code is heavier than needed for a first look at recursion: record dicts, list concatenation, and a depth parameter bury the simple n * factorial(n-1) idea. The 'try' suggestion to remove depth and record['depth'] is also a muddled exercise, and the text never explains the log-building lines.
- picture: The quiz is fine but the distractor 'The loop would just stop at n = 1' mentions a loop that doesn't exist, and the text says 'every branch' reaches the base case when there is only one chain. The Russian doll analogy is decent, but the text never connects the returns (unwinding) to the multiplication, which is the key insight the table shows.
- picture: Line 15 hardcodes a call tree that omits factorial(5)=120 and only shows 0! through 4!.

**`antigravity:flash-low`**
- picture: Text contradicts the code and picture: the intro and title frame recursion as a simple 'loop' / nesting dolls (a linear chain), but countdown calls itself twice, so it produces a 15-node binary tree. The doll analogy never matches the branching, and the lesson doesn't explain why it branches, which adds confusion for a beginner.
- picture: Function name 'countdown' is misleading: it never counts down or prints anything, it builds a dict tree with 2 recursive calls per level (exponential growth). A single-call version (e.g. factorial or sum to n) would show the core idea. The picture shows 15 nodes with unexplained values (0,0,1,...,3) and the lesson never explains how to read them. Also the text says 'folding back up into a single nested dictionary', which is not what the learner sees (a tree drawing).
- picture: Quiz and try-it are weak or flawed: the quiz answer is okay in principle, but deleting lines 2-3 also gives a RecursionError rather than 'memory limits' (it's the recursion depth limit, not memory). The 'try' items are bare commands with no prediction of what to expect, and 'Swap n - 1 with n - 2' can skip past 0 (e.g. n=3 -> 1 -> -1, fine here, but the base case n <= 0 only coincidentally saves it). Also the text says 'lines 4 and 5' ask to solve n-1 but never mentions line 6, the combine step.
- picture: The Russian doll analogy describes single/linear recursion, which contradicts the code's branching binary tree.

**`claude:haiku`**
- picture: The text promises a tree of every call to total(4), but show() only outputs the text '10 1+2+3+4'. No tree is drawn, so the user's request for a picture goes unmet and the lesson refers to something that isn't there.
- picture: Line references are off: the text says line 11 is 'Adding this number', but line 11 is the `if n == 0` check; the combining happens on line 13. The try-it also says to remove the `return 0` line, but the quiz and margin note talk about the `if n == 0` check, which is confusing. Removing only `return 0` leaves an empty if body (a syntax error), not the RecursionError the learner is told to expect.
- picture: The quiz answer says Python 'runs out of memory and crashes', while its explanation correctly says Python raises a RecursionError at a depth cap. The two statements contradict each other. The lesson also never traces total(4) with concrete values (4 + total(3) -> 3 + total(2) ...), and the 'n + 1' try-it is untested. Two functions are introduced at once, which dilutes the focus.
- picture: The text promises a tree drawing of the calls, but show() only produced plain text displaying '10 1+2+3+4'.
